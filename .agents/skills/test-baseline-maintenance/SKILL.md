# Test Baseline Maintenance

## 适用边界

- 仅审查变更涉及的测试及依赖；不影响行为或测试风险的文档、格式修改，可不调整测试。
- 沿用项目测试约定、命令和质量门禁；本 Skill 不额外要求新框架、辅助脚本或覆盖率阈值。

## 审查现状

- 结合已确认需求、契约、项目文档、代码和测试确定预期；实现与现有测试不是业务正确性的唯一依据。
- 纯重构保持有效行为和断言语义；仅在契约变化或原测试与已确认要求冲突时调整预期。
- 按影响审查相关测试、夹具及 Mock 的覆盖和稳定性，关注公共契约、系统不变量、边界、权限、数据一致性、并发恢复、兼容性和历史缺陷；行为不明、测试结构调整或回归风险较高时，结合验证成本优先运行相关测试建立变更前基线。

## 维护决策

| 判断                           | 动作               |
| ------------------------------ | ------------------ |
| 测试仍有效且稳定               | 保留               |
| 契约变化或预期与已确认要求冲突 | 更新相关测试与断言 |
| 组织或重复问题影响维护         | 整合用例或夹具     |
| 测试失效或冗余                 | 核实覆盖承接后清理 |
| 存在重要覆盖缺口               | 新增最小充分的测试 |

- 新增或补充用例前明确覆盖缺口、有效行为或独立失败模式及回归后果，权衡独立保护价值与执行、维护成本；能补充现有测试时优先补充。高风险而覆盖不明时继续核查，代码或覆盖率变化本身不构成新增理由。
- 围绕公共契约、组件职责和系统不变量选择关键等价类与边界，避免过度绑定实现、冗余 Mock 和同一风险的重复输入或断言。
- 清理、迁移或整合前，确认独有断言及风险保障已保留、有可靠等效覆盖或已不再适用；保留隔离性和故障定位能力。
- 行为移除的一次性验证可用临时测试；持续的禁止性约束、安全要求或关键回归风险保留为长期测试，验证记录按项目留存要求处理。

## 核验与汇报

- 按变更风险选择测试层级，运行受影响及必要的相邻回归；跨模块真实交互优先集成验证，高风险变更按需扩大范围。
- 区分契约变化、真实回归、测试失效和环境问题，不通过改变正确行为、弱化或跳过有效验证掩盖失败。
- 复核新增或调整用例是否补足缺口并能识别目标错误；重要缺陷修复在安全可行时验证修复前失败、修复后通过。
- 在常规变更说明中交代维护动作与原因、实际执行结果及未验证事项；未调整测试时说明原因，存在已知覆盖缺口或残余风险时一并说明。不另建报告，除非有明确交付、持续使用或留存需要。
