# Documentation Baseline Maintenance

## 适用边界

- 仅审查当前文档任务或系统变更涉及的文档及必要引用；不影响已记录行为、契约或使用方式的内部变更，可不修改文档。
- 沿用项目的目录、风格、生成流程和留存要求；本 Skill 不额外要求新工具或模板。

## 审查现状

- 独立编写、审查或重构文档时，明确主题、读者和用途；系统变更时，确认受影响的文档范围。
- 结合已确认需求、契约、设计决策、代码和测试核实事实；实现与明确契约冲突时先核实，不为迎合实现改写契约。
- 定位权威文档及相关入口，检查失效、重复、冲突和信息缺口；区分当前、规划及废弃内容，有版本或环境差异时注明适用范围，不将推测或草案作为现状。

## 维护决策

| 判断                               | 动作                                 |
| ---------------------------------- | ------------------------------------ |
| 内容准确且仍有用途                 | 保留，无需为整理而修改               |
| 有效行为、契约或使用方式变化       | 更新权威内容、示例及引用             |
| 内容重复、职责混杂或位置不当       | 整合或重组，保留独有信息及可发现性   |
| 内容失效且无持续价值               | 清理或归档，先核实历史和留存要求     |
| 存在现有来源无法合理承载的信息缺口 | 新增最小必要内容，接入相关索引或入口 |

- 自解释性以职责和目标读者为界：正文交代主题、适用范围及必要背景、关键行为与约束摘要；完整定义和详细规范由权威来源维护，通过引用补充细节，避免重复维护完整规范或相互矛盾。
- 保持内容内聚，避免为缩短篇幅过度拆分紧密相关内容，或为减少文件数强行合并不同受众或职责的文档。
- 核心定义或约束对其他文档的依赖属于规范性依赖，方向应明确且不成环；仅用于导航或扩展阅读的链接可双向引用。
- 新增文档应有独立主题、明确读者和持续参考价值；一次性总结、临时分析和排障记录仅在有持续价值、明确交付或留存要求时进入长期基线。
- 整合、迁移或清理前，确保仍有效或需留存的独有信息、操作知识和历史已保留或可靠承接，并修复受影响的入口与引用。
- README 等当前文档反映有效状态；ADR、CHANGELOG 和迁移记录通过状态或后续记录说明被取代的决策，不静默覆盖或删除必要历史。

## 核验与汇报

- 核对最终内容的事实、适用范围和独立价值，以及受影响的路径、命令、配置、接口、链接、锚点和导航；有生成源时优先修改源文件，条件允许时验证重要命令与示例。
- 按目标读者复核主题与边界是否清楚、必要说明是否充分、规范引用是否明确；检查完整规范是否重复维护、规范性依赖是否成环。
- 在常规变更说明中交代维护动作及原因、实际核验结果和未确认事项；未修改文档时说明原因。不另建报告，除非有明确交付、持续使用或留存需要。
