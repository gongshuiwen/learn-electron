# Documentation Baseline Maintenance

## 目标与边界

让文档随有效系统契约持续演进，以最小必要的维护成本保持**准确、一致、可发现、可追溯**；不以文档数量、篇幅或新增文件数衡量产出。

- 仅审查当前变更影响的文档及必要引用，不扩大到无关整理；不影响已记录行为、契约或使用方式的内部变更，可不修改文档。
- 遵循项目现有目录、文档分类、风格、生成流程及监管或审计留存要求；不强制引入新工具、模板或文档平台。

## 工作流

### 1. 确认变更影响与事实依据

- 识别受影响的用户操作、公共接口、配置、部署步骤、架构职责、兼容性及故障处理方式；无关项无需展开。
- 结合已确认需求与契约、代码、配置、测试和正式设计决策核实事实；**当前实现不一定代表正确的预期行为**，存在冲突时先核实，不为迎合实现而篡改明确契约。
- 区分**当前有效、规划中、已废弃**的内容；不得将推测、草案或未实现能力描述为现状；不同版本与环境应明确适用范围。

### 2. 审查现有文档与信息缺口

- 定位相关 README、使用指南、接口与配置说明、架构和部署文档、ADR、CHANGELOG 及索引，识别现有权威位置。
- 检查内容是否失效、重复、冲突、职责混杂或不易发现，以及是否存在实际信息缺口。
- **优先维护单一权威来源**：详细规则、参数与操作说明尽量集中维护，其他位置通过摘要和链接引用；不同受众的必要概述可以保留，但不得相互矛盾。
- **新增文档准入检查**：先明确独立主题、目标读者、持续参考价值及现有文档无法合理承载的原因；能通过补充现有章节或更新引用解决时，不新增文件。

### 3. 选择最小必要的维护动作

| 判断                             | 动作                                         |
| -------------------------------- | -------------------------------------------- |
| 现有内容准确且仍有用途           | **保留**，无需为整理而改动                   |
| 有效行为、契约或操作方式变化     | **更新**权威内容、示例及必要引用             |
| 内容重复、职责混杂或放置不当     | **整合/重组**，保留独有知识和可发现性        |
| 当前状态说明失效且不再有持续价值 | **清理/归档**，先核实历史、引用及留存要求    |
| 存在独立且持续有用的信息缺口     | **新增**最小必要内容，并接入合适的索引或入口 |

- **当前状态文档与历史记录分离**：README、指南、API 和部署说明反映当前有效状态；ADR、CHANGELOG、迁移记录等保留必要历史，通过状态、后续记录或引用说明被取代的决策，不静默改写或删除。
- 一次性任务总结、临时分析、排障流水账默认不进入长期文档基线；有持续参考价值、明确用户要求或留存义务时除外。
- 删除、合并、迁移前确认独有信息、关键操作知识和历史记录已保留或可靠承接，并修复相关入口、链接和引用；不为压缩文件数量而强行合并不同受众或职责的文档。

### 4. 核验内容并简要汇报

- 根据可靠来源核对文件路径、命令、配置项、环境变量、API 字段、版本约束及架构关系；条件允许时实际验证重要命令与示例。
- 检查受影响的导航、相对链接、锚点及交叉引用；存在文档生成源时优先修改源文件，而非仅修改生成产物。
- **新增后独立价值复核**：确认新内容填补实际信息缺口、位于合适的权威位置且不会形成不必要的重复维护；缺乏独立价值时调整、整合或移除，并遵守第 3 步的信息与历史承接条件。
- 无法核实或存在分歧时标明限制，不以猜测填补细节，也不得声称未执行的验证已通过。
- 在常规变更说明中简述关键维护动作及原因、实际核验结果与未确认事项；未修改文档则简述原因。**不另建任务总结报告**，除非有明确要求或持续使用价值。
