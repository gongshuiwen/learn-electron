# 测试指南

以下命令均在仓库根目录执行；环境安装见 [README](../README.md#环境)。自动化测试不需要真实模型密钥。

Web 界面测试使用 Playwright 和本机 Chrome，可用 `PLAYWRIGHT_CHANNEL=msedge` 切换 Edge。

## 日常验证

测试随所属应用或包维护，按改动影响选择工作区或目标用例：

| 验证范围                     | 命令                                          |
| ---------------------------- | --------------------------------------------- |
| 指定工作区（以 server 为例） | `npm test --workspace @learn-electron/server` |
| 全部工作区测试               | `npm test`                                    |
| 全仓库静态检查               | `npm run check`                               |
| 桌面冒烟与完整集成测试       | `npm run test:desktop`                        |
| 桌面启动与聊天链路           | `npm run test:desktop:smoke`                  |

CI 在各平台运行连接核心、认证包、contracts、后端、Runtime 和桌面测试，并在 Windows 运行 Web 测试。桌面 CI 使用 `npm run test:desktop` 执行冒烟与完整集成测试。根目录的桌面测试入口统一使用 `test:desktop` 前缀，转发到桌面工作区的 `test`、`test:smoke` 和 `test:packaged`；工作区的准备钩子会自动执行。其他测试命令见 [根脚本](../package.json)与各工作区的 `package.json`。

## 定向测试

通过 npm 测试脚本运行时，已声明的 `pretest` 等准备步骤会自动执行；直接运行 `node --test` 会跳过这些步骤。

桌面和 Web 界面测试需要与当前源码匹配的构建产物，单文件运行前先执行所属工作区的 `pretest`。后端、contracts 和 Runtime 测试不依赖桌面产物。

后端可按层定向运行，例如：

```powershell
npm run typecheck:server
node --import tsx --test --test-concurrency=2 "apps/server/test/http/*.test.mjs"
```

将 `http` 换成 `component` 或 `integration` 可运行其他层；`npm run test:server` 递归执行全部后端测试并自动运行类型检查。

桌面单文件测试示例：

```powershell
npm run pretest --workspace @learn-electron/desktop
node --test --test-concurrency=1 apps/desktop/test/integration/lifecycle.test.mjs
```

构建输入未变时可以复用产物；变更后重新准备，避免用旧构建验证新源码。桌面测试按文件串行执行。

后端和 Web 测试入口各最多同时运行两个文件，控制真实 Pi、浏览器启动和 Windows 凭据目录权限设置的资源竞争。直接运行多个相关测试文件时也应指定 `--test-concurrency=2`。测试夹具清理目录前等待进行中的启动、重启、子进程退出及 stdio 结束；IPC 入口另等待通道断开，避免依赖显式断开 IPC 后可能缺失的进程 `close` 事件。目录删除对 Windows 短暂占用进行有限重试。

## 覆盖范围

| 层次      | 主要验证内容                                     |
| --------- | ------------------------------------------------ |
| Web       | HTTP 客户端、浏览器界面与模拟 API 交互           |
| 后端      | HTTP/SSE 与 SQLite                               |
| 连接核心  | 纯配置与选择校验、模型引用、协议兼容及凭据头边界 |
| 认证包    | 独立存储接口、账号凭据隔离与授权模型元数据       |
| contracts | 协议校验                                         |
| Pi 适配   | 离线验证真实 session 与上下文持久化              |
| 桌面集成  | 真实本地后端与 mock 引擎的集成链路               |

崩溃恢复测试覆盖正常恢复与恢复启动阶段的超时取消。取消回归用受控 Promise 暂停启动，验证启动结束、服务关闭、目录删除的顺序，并检查取消后不再执行后续恢复操作。

后端测试按被测入口组织：`component` 直接验证服务和存储，可使用真实 SQLite 与本地 OAuth 夹具；`http` 使用真实 HTTP/SSE 连接；`integration` 覆盖跨模块、进程与生命周期。共享夹具放在 `helpers`。HTTP 测试覆盖 Host、Origin、Bearer 与预检顺序、路由方法、按需读取正文及大小边界；关闭回归读取 SSE 至正常结束，并核对中断事件。

SSE 快照准备包含异步模型状态读取，回归覆盖准备期间任务结束和客户端断开：返回最新终态，或释放新建订阅，不留下等待中的连接，也不取消模型生成。

通用连接测试使用本地四种协议上游与真实 Pi，覆盖前端配置 API、手填模型、目录发现、独立测试、字面值凭据、不回显、无认证、跨连接隔离、配置保存失败、取消与重启续聊。测试目标无效时也必须释放更新互斥，后续操作仍可执行。浏览器集成从空配置添加自定义提供商、测试、聊天、编辑与重载恢复，检查密钥不进入浏览器存储及移动端表单；验证缺少凭据和模型时的提示、保存及测试进行中的状态，以及保存期间不能误关表单。ChatGPT 登录仅在订阅预设和账号详情中出现，切换供应商时授权仍能完成。旧环境模型凭据被忽略，不承接为配置兜底。安全回归对四种协议的真实生成与连接测试返回跨源 307，并覆盖改变请求方法的 303，确认目标服务没有收到任何请求；401、429、404 生成失败保留分类错误码且不泄漏上游内容。

ChatGPT 测试使用本地 OAuth/Responses 服务及真正签名的 ID token，不读取用户凭证或访问真实模型。后端覆盖 JWKS 身份校验、注册复用、权限不足、取消/超时、令牌轮换与账号上下文归属；多账户回归验证按 ID 解析凭据、失败只影响指定账户，退出一个账户时另一个仍可用。HTTP 集成覆盖 `PUT /model` 的完整目标、无效模型不改变原选择、真实 Pi、SSE、重启续聊和失败不回退 API Key；未选中账户的连接测试不写会话或切换目标，修改默认选择后，已绑定会话继续使用原账号令牌与原生上下文，新会话使用新选择；两个 ChatGPT 实例同时生成时，退出其中一个只取消它的任务。混合连接回归覆盖登录成功、取消、失败、超时、重启与迟到响应都保留原目标，显式选择保存失败保留原连接和有效凭据，注销非活动账户不取消其他连接任务，注销活动账户仍取消其任务；其他实例的授权过程不暂停当前实例。

认证包的独立测试使用内存存储验证多账号隔离和原始授权目录；后端集成验证运行时不支持的模型不会对外提供，现有 v2 凭据文件可继续使用。

数据格式回归覆盖旧模型连接文件、旧 ChatGPT 凭据文件、无版本及旧版 SQLite 数据库，以及未来版本数据库；验证拒绝打开时不改写原文件和记录。当前格式的模型、凭据、会话绑定和原生上下文在重启后保留；演示会话不能切换到真实模型续聊。

授权生命周期回归用受控 Promise 暂停退出、令牌刷新和回调监听启动：退出期间拒绝同实例重新授权，其他实例仍可申请；关闭时拒绝排队登录、关闭启动中的监听器，同时确认已开始的令牌轮换完成保存。退出中的关闭分别等待任务停止、远程撤销和凭据保存，退出失败也会释放等待；双服务重启回归验证目录锁释放后其他账号和新实例均保留。用例不依赖固定延时，清理前等待相关异步操作结束。

依赖边界回归在隔离目录中使用仓库的导入规则，检查认证包、连接核心、后端核心、Runtime、Web 和桌面对包子路径的限制，并验证允许的依赖不受影响。

直接选择回归覆盖同供应商多实例、显式选择、默认值改变、重启和目标实例移除：已绑定会话保留原目标，失效目标不回退。

并发与失败回归覆盖会话快照与选择的一致性、不同客户端切换空会话后的目标校验、ChatGPT 测试期间同实例退出和重新授权、不同账号同时刷新令牌及其他账号退出期间仍可取令牌，以及删除账号时两份文件分别保存失败后的重试。连接测试的认证及权限失败只更新对应账号。浏览器验证迟到的模型元数据不会覆盖较新结果，发送使用界面显示的目标；删除部分失败后刷新默认值，登录启动失败后复用新实例，保存成功但刷新失败时关闭表单并提示。账号授权中和更新中的状态及同邮箱实例的显示区分也有覆盖。

Web 验证聊天页初次加载不读取连接配置，展开快捷选择器后才读取脱敏实例和所选 ChatGPT 模型缓存，不调用模型；进入独立设置页后只有一次统一连接状态读取。覆盖设置路由刷新、前进后退、草稿保留和生成不中断。实例列表浏览、登录、保存和测试都不切换默认值，点击“设为默认模型”才提交，定向注销后状态一致。登录恢复回归分别验证轮询、取消遇到 `404 login_not_found` 后结束旧尝试并重新登录，以及临时错误时保留进行中的登录。真实浏览器、后端及 Pi 的集成在授权中于同一端口重启后端，验证页面不刷新、跨聊天与设置页保留草稿、重新授权后完成两轮上下文聊天；保留授权进度刷新恢复、历史重载和退出检查，并区分添加账户与重新授权的请求。快捷选择回归覆盖实例与模型选择、取消浏览、空会话原地修改、失败后保留草稿并重试，以及已有会话切换后保留历史、使用新实例凭据且不转发旧上下文；验证默认值不变、迟到快照不覆盖新选择、生成期间禁用、移动端弹层、深色模式和 ChatGPT 账号的缓存目录。后端同时验证空会话选择更新的序号、无效选择回滚及绑定后拒绝修改。桌面测试验证设置路由与刷新后的 IPC、受限浏览器入口和 PUT 代理。Web 测试入口使用 `tsx` 加载后端 TypeScript。

Pi 代理回归使用独立 Node 进程和真实本地 HTTP 代理，验证 SDK 初始化前后都经过环境代理，以及 `NO_PROXY` 对回环请求的绕过；不替换 `fetch` 或访问外网。

自动化测试不覆盖真实提供商网络连接；页面恢复测试不验证操作系统原生崩溃事件投递。

真实账户验收直接在界面连接 ChatGPT：在系统浏览器授权计划使用，选择账户和模型并点击“使用此模型”，连续发送两轮消息，重启应用后续聊，查看 ChatGPT 用量设置，再验证退出和重新授权。检查真实上游成功前，不将模拟授权测试视为订阅可用性的证明。网络、账户/工作区政策及上游权限失败应记录实际状态，不关闭 TLS、绕过站点验证或改用 API Key。

## 交付验证

发布前需在 Windows 显式运行以下命令；该验证不在常规 `npm test` 或 CI 中：

```powershell
npm run test:desktop:packaged
```

该命令通过桌面工作区的 `pretest:packaged` 准备 `win-unpacked` 应用，并复制到仓库外，验证无系统 Node 的运行、历史恢复、后台进程清理、生产 Pi 依赖的离线加载，以及默认可用的 ChatGPT 登录所需的 `jose`、Windows 凭证目录权限和登录入口；NSIS 安装/卸载、签名和更新按任务需要另行验证。
